# 灰燼歸路 MVP 計畫

目標：既有 2D 入口增加可完整玩完的回收撤離任務，附獨立美術目標圖。
規格：根目錄 art-direction/86-reference/chapter-design.md 的 2026-09-13 草案；本輪只做一關，保留原作職能與改編界線。
技術：沿用 Canvas、GameArenaCore、DOM 選單、現有音效與機體素材，不新增框架。

- [x] 規則：GameCampaign 包裝既有核心；連續地圖、有限遭遇、E 開始／取消回收、離開自動取消、救援可選、撤離勝利；測未回收不能過關／可選不必要／重開清理／無限模式不受影響。
- [x] 介面：主頁與整備皆可選作戰篇章，任務固定 M1A4；保留既有控制與開結場；地面節點、雷達、精簡目標面板、通訊、結果摘要。
- [x] 美術：imagegen 單張實際遊戲比例目標稿；MVP 使用既有素材加道路／節點／地標，不把目標稿宣稱成實機。
- [x] 整合：規則回歸、瀏覽器輸入與勝敗／重試流程，具體說明受控測試與真人驗收差異。
- [x] 交付：完成增量同步根目錄8765，不重啟服務；Issue→PR→Review，確保新增檔案進靜態發布清單；更新記錄。

分工：一位輕量 Agent 寫關卡規則與測試；主 Agent 製作美術、整合 UI、驗收與 Git 流程。只使用這一輪最小範圍。


## Sprint Review / Retro（2026-09-13）

- 玩家故事：我想駕駛既有 2D 機甲執行有目的的局部任務，能選擇救援或直接撤離。
- 本輪界線：單張美術目標圖 + 一關短 MVP；8 個有限遭遇敵機，不新增 3D、建模或引擎。
- 實際路線：自動腳本使用真實鍵鼠事件、加速時間及狀態輔助瞄準；約 18 秒遊戲時間完成最短外側路線，留下 4 隻敵機。這只能證明流程可完成，不能宣稱完成 8–12 分鐘章節，也不是人類難度 QA。
- 瀏覽器驗收：主頁／整備／開始、回收開始與取消、完成回收、外側撤離、勝利、重試重置、受控死亡；無頁面 JS 錯誤。人工查看整備、戰鬥與結果截圖。
- 單元測試覆蓋未回收不能撤、帶物資自動撤、救援可選、回收分段、死亡優先、彈種、補給、敵軍上限、外緣繞行。
- 獨立 reviewer：只讀規則與整合路徑，未發現阻擋缺陷；沒有冒稱實際玩過。
- 修正：回收進度從百分數誤讀修正；入口 E 提示和規則範圍一致；撤離改自動觸發；外緣通道加寬。
- Retro：先辨識腳本容差與真實地形問題，不為了測試能過而修改玩家平衡。下一輪先問玩家路線、目標與可選救援的價值；美術稿與實機差距仍需明確標示。
- 資源：本輪核對已用 73%，沿用玩家追加 10% 的上限，保留至少 20%；未兌換額度。
